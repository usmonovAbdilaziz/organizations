# SEO Architecture Documentation

## Overview

This document describes the SEO architecture for the Afitsant organization directory. SEO is managed automatically through a centralized `SeoService` that handles metadata generation, storage, and retrieval for all entities.

## Architecture

### Design Principles

1. **No Direct Prisma Relations**: The `Seo` model has no direct relations with other entities. It uses `entityType` and `entityId` to establish connections.

2. **Automatic Generation**: SEO metadata is automatically generated when entities are created unless custom SEO data is provided.

3. **Centralized Service**: All SEO operations go through `SeoService`, ensuring consistency and avoiding code duplication.

4. **Clean Architecture**: Entity services (OrganizationService, CategoryService, etc.) delegate SEO operations to SeoService.

### Service Hierarchy

```
CategoryService        → SeoService
OrganizationService    → SeoService
ServiceService         → SeoService
RegionService          → SeoService
DistrictService        → SeoService
```

## Seo Model

### Schema

```prisma
model Seo {
  id String @id @default(cuid())

  // Entity identification
  entityType SeoEntity
  entityId   String

  // Meta Title
  titleUz String? @db.VarChar(255)
  titleRu String? @db.VarChar(255)
  titleEn String? @db.VarChar(255)

  // Meta Description
  descriptionUz String? @db.Text
  descriptionRu String? @db.Text
  descriptionEn String? @db.Text

  // Keywords
  keywordsUz String? @db.Text
  keywordsRu String? @db.Text
  keywordsEn String? @db.Text

  // Canonical
  canonical String?

  // Robots
  robots String? @default("index,follow")

  // OpenGraph
  ogTitleUz String?
  ogTitleRu String?
  ogTitleEn String?
  ogDescriptionUz String? @db.Text
  ogDescriptionRu String? @db.Text
  ogDescriptionEn String? @db.Text
  ogImage String?

  // Twitter
  twitterTitleUz String?
  twitterTitleRu String?
  twitterTitleEn String?
  twitterDescriptionUz String? @db.Text
  twitterDescriptionRu String? @db.Text
  twitterDescriptionEn String? @db.Text
  twitterImage String?

  // JSON-LD
  schema Json?

  // Auto SEO flag
  autoGenerated Boolean @default(true)

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([entityType, entityId])
  @@index([entityType])
}

enum SeoEntity {
  CATEGORY
  ORGANIZATION
  SERVICE
  REGION
  DISTRICT
}
```

### Unique Constraint

The `@@unique([entityType, entityId])` constraint ensures no duplicate SEO records exist for the same entity. This is used by `SeoService.upsertSeo()` to determine whether to create or update.

### Methods

#### findSeo(entityType, entityId)

Finds SEO record by entity type and ID.

```typescript
async findSeo(entityType: SeoEntity, entityId: string) {
  return this.prisma.seo.findUnique({
    where: {
      entityType_entityId: {
        entityType,
        entityId,
      },
    },
  });
}
```

#### upsertSeo(entityType, entityId, seoData)

Creates or updates SEO record. Uses the unique constraint to determine operation.

```typescript
async upsertSeo(
  entityType: SeoEntity,
  entityId: string,
  seoData: Partial<CreateSeoDto>,
) {
  const existing = await this.findSeo(entityType, entityId);

  if (existing) {
    return this.prisma.seo.update({
      where: {
        entityType_entityId: {
          entityType,
          entityId,
        },
      },
      data: seoData,
    });
  }

  return this.prisma.seo.create({
    data: {
      entityType,
      entityId,
      ...seoData,
    },
  });
}
```

#### updateSeo(entityType, entityId, seoData)

Updates existing SEO record only. Returns null if not found.

```typescript
async updateSeo(
  entityType: SeoEntity,
  entityId: string,
  seoData: Partial<CreateSeoDto>,
) {
  const existing = await this.findSeo(entityType, entityId);
  if (!existing) {
    return null;
  }

  return this.prisma.seo.update({
    where: {
      entityType_entityId: {
        entityType,
        entityId,
      },
    },
    data: seoData,
  });
}
```

#### deleteSeo(entityType, entityId)

Deletes SEO record for an entity.

```typescript
async deleteSeo(entityType: SeoEntity, entityId: string) {
  return this.prisma.seo.delete({
    where: {
      entityType_entityId: {
        entityType,
        entityId,
      },
    },
  });
}
```

#### Create

```typescript
async create(createOrganizationDto: CreateOrganizationDto) {
  const { name, categoryId, inn, seo } = createOrganizationDto;

  // ... validation and slug generation ...

  const newOrganization = await this.prisma.$transaction(async (tx) => {
    const organization = await tx.organization.create({
      data: { ...orgData, slug },
    });

    if (seo) {
      // Use custom SEO
      await this.seoService.upsertSeo(SeoEntity.ORGANIZATION, organization.id, {
        ...seo,
        autoGenerated: false,
      });
    } else {
      // Auto-generate SEO
      const city = primaryBranch?.district?.region?.nameUz;
      const categoryName = category.nameUz;

      const generatedSeo = this.seoService.generateOrganizationSeo({
        name,
        category: categoryName,
        city,
        slug,
      });

      await this.seoService.upsertSeo(SeoEntity.ORGANIZATION, organization.id, generatedSeo);
    }

    return organization;
  });
}
```

#### Find One

```typescript

  const organization = await this.prisma.organization.findUnique({
    where: { id },
    include: { users: true, branches: true, category: true },
  });

  const seo = await this.seoService.findSeo(SeoEntity.ORGANIZATION, id);

  return {
    ...organization,
    seo,
  };
}
```

#### Update

```typescript
async update(id: string, updateOrganizationDto: UpdateOrganizationDto) {
  const { seo, ...orgData } = updateOrganizationDto;

  await this.prisma.$transaction(async (tx) => {
    await tx.organization.update({
      where: { id },
      data: orgData,
    });

    if (seo) {
      await this.seoService.upsertSeo(SeoEntity.ORGANIZATION, id, {
        ...seo,
        autoGenerated: false,
      });
    }
  });

  return this.findOne(id);
}
```

#### Remove

```typescript
async remove(id: string) {
  await this.seoService.deleteSeo(SeoEntity.ORGANIZATION, id);

  return await this.prisma.organization.delete({
    where: { id },
  });
}
```

## Business Rules

### 1. No Duplicate SEO

The `@@unique([entityType, entityId])` constraint prevents duplicate SEO records. The `upsertSeo` method uses this to determine whether to create or update.

### 2. Auto-Generated vs Custom SEO

- If `seo` object is provided in create/update DTO: Use custom SEO with `autoGenerated: false`
- If `seo` object is NOT provided: Auto-generate SEO with `autoGenerated: true`

### 3. SEO Deletion

When an entity is deleted, its SEO record is also deleted to maintain data integrity.

### 4. Bulk Loading

For `findAll()` methods, SEO is loaded in bulk to avoid N+1 queries:

```typescript
const entities = await this.prisma.entity.findMany();

const entityIds = entities.map((e) => e.id);
const seoRecords = await this.prisma.seo.findMany({
  where: {
    entityType: SeoEntity.ENTITY_TYPE,
    entityId: { in: entityIds },
  },
});

const seoMap = new Map(seoRecords.map((seo) => [seo.entityId, seo]));

return entities.map((e) => ({
  ...e,
  seo: seoMap.get(e.id),
}));
```

### 5. Transaction Safety

All create/update operations that involve SEO are wrapped in Prisma transactions to ensure atomicity.

## Troubleshooting

### SEO Not Showing in Response

1. Check if SeoModule is imported in the entity module
2. Verify SeoService is injected in the constructor
3. Ensure `findSeo` is called after entity is fetched
4. Check database for existing SEO record

### Duplicate SEO Records

1. Verify `@@unique([entityType, entityId])` constraint exists
2. Ensure `upsertSeo` is used instead of direct `create`
3. Check for manual SEO creation bypassing SeoService

### Auto-Generation Not Working

1. Verify SEO object is not included in DTO
2. Check if generation method exists for entity type
3. Ensure required data (name, slug, etc.) is available
4. Check translation utility is working

## Summary

The SEO architecture provides:
- **Centralized SEO management** through SeoService
- **Automatic generation** for all entities
- **Custom SEO support** when needed
- **No duplicate records** through unique constraints
- **Transaction safety** for atomic operations
- **Bulk loading** for performance
- **Clean architecture** with separation of concerns
- **Scalability** for future entity types
